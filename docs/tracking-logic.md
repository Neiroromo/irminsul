## 0. Общее
- Трафик: пакеты игры (KCP), расшифровка ключом сессии. Ключ хранится в `session_key.bin`, KCP при подключении посреди сессии сдвигается на первый виденный номер сегмента (`skip_to` в `vendor/auto-artifactarium/src/kcp.rs`); `GameCommand.from_client` отличает команды клиента от сервера.
- Команды (версия 2026-11; меняются с патчами): 20584 позиция игрока раз в 6 с (в поле 13 поворот yaw, в 14 позиция); 24007/5791 от клиента: движение (пользуйся для карты, не для выводов); 4469 объекты появились (гаджеты: id, группа, config, состояние); 20297 взаимодействие (kind 3 = сундук); 7608 изменение предметов (приходят дельты только при полном списке); 27748 вход в сцену; 26942 телепорт (id точки); 897 весь список заданий при входе; 26691 история обновилась; 24303 шаг задания (id, состояние 1..4, история); 4955 переменные шага.
- Координаты: пиксель карты = (−s·z + a, −s·x + b); мир: s=1, a=−750, b=2321. Метки официальной карты смещены относительно объектов до ~12–30 px: сопоставление по ближайшему объекту И середине группы, допуск 14–32 px.
- Наблюдение: игра присылает только невыполненное. Радиус: в ходу ~100–130 м (многие виды 190–260 м), при входе в сцену до ~580 м, некоторые виды «из любого места» (70800xxx, 70620xxx, 70950xxx, 73122xxx), одиночный окул 70520017 только ближе ~30 м (в пачке при входе его нет).
- Правило безопасности: «не прислано» считается выполненным только для вида, про который известно, что его присылают на этом расстоянии. Любое присланное позже возвращает «не выполнено» (доверяем игре).

## 1. Сундуки (включено)
- Мир: `chests.rs` (трекер: гаджет сундука → найден; открытие по событию 20297 kind 3 и по наградам 7608 в окне 3 с), покрытие `coverage.rs` (прошёл рядом, сундука нет → «скорее всего открыт»).
- Другие карты (Энканомия и т. д.): `chest_watch.rs`. Сундук прислан → закрыт; состояние 102 или открыл → открыт; прошёл ≤ радиуса радара дважды (трижды, если далеко) и не прислан → открыт. Радиус радара 40–130 м (настройка), подстраивается под наблюдаемую дальность сцены.
- Открытый сундук, которого не видели при подключении (программу запустили позже): привязка к ближайшему неоткрытому сундуку того же уровня в 14 м / 25 м по высоте от игрока (`chests::chest_by_player`).

## 2. Окулы и феи (`object_watch.rs`, выключено)
- Соответствие «вид объекта игры ↔ вид метки»: затравка (фея 70710010; окул 70520017 — только вблизи; 70800004/08/09/07 — из любого места) + обучение по совпадению позиций (≥4 наблюдений, ≥80 % на один вид).
- Класс присылки (Local / Bulk / Anywhere) определяется по расстояниям первого появления. Проверка «отсутствует при входе» только для Bulk/Anywhere в пределах 420 м; одиночный окул так не проверять.
- Фея: двор (70710006/07) состояние 203 = выполнена; метка фей сопоставляется объекту в 16 px.

## 3. Головоломки и испытания (`puzzle_watch.rs`, выключено)
- Объекты головоломки и сундук-награда в одной группе игры (group_id). Выполнено, если: сундук открыт (событие, entity → группа) или сундук (состояние None, не 101) появился позже остальных объектов группы (≥4 с) пока игрок ≤50 м от него.
- Метка = ближайшая из группы «Сокровища с загадкой» (186) к объекту группы или к середине группы, ≤32 px, единственная (вторая не ближе чем в 1,5 раза).
- Выполненные: монумент/пилларсы 70900007 состояние 201 (невыполненные 901), двор феи 203, шары 70360008 состояние 203; остальные объекты выполненной головоломки (камни, факелы, испытание на время) исчезают из присылки → проверка по отсутствию (вход: до 250 м, на время/шары до 200/120 м; в ходу ~половина: 100/80/60/180/80/90 м, два отчёта подряд).
- Откат: объекты пришли к метке, отмеченной по отсутствию → снять.
- Подбор: предмет +1..3 при полном списке, метка с тем же английским названием ≤8 м → собрана; срок возврата берётся из метки (`refresh`), у руды 72 ч (предположение).

## 5. Диагностика, которую оставил
- `census-<дата>.log`: гаджеты (сцена, entity, id, группа, config, состояние, позиция), строки `quest`, `story`, `queststory`.
- `track-<дата>.log`: все отчёты позиции (сцена, позиция, yaw, этаж, карта).
- `commands in 20 s` в таймлайне: счётчик команд по типам.

## 6. Как вернуть всё включённое
1. `EXTRA_MARKS = true` в `src/monitor.rs`.
2. Из ручных отметок учитывать только виды, которые собираются один раз (см. раздел 7).

## 7. Ручные отметки на карте (Map)
- Отметить «собрано» можно только то, что собирается один раз и больше не появляется (окулы, сундуки, головоломки, находки). Всё, что сбрасывается (враги, растения, руда, диковинки, древесина, животные, рыба, полевые подборы), пока нельзя.
